Release Notes

Experimental test build. Fixes the AnyPS5 startup crashes of 0.9.92-test (AGC driver memory: File exists) , 0.9.93-test (overlapping guest allocation) and 0.9.94/0.9.95-test (cannot query guest memory; Android tagged pointers) , 0.9.96-test (missing sceAgcCbNop and other _nid_postfix exports) and 0.9.97-test (tagged heap pointers treated as guest VA slots). AnyPS5 reaches the Wonder Boy title screen on device; 0.9.99 fixed its sideways image and per-memory-call GPU drains; 0.9.100 stopped per-frame swapchain rebuilds, filled the screen and fixed the fused-shader crash; 0.9.101 registers guest heaps with write tracking; 0.9.102 reported whether that tracking is available; 0.9.103 adds Android write tracking on Kyty's own page-fault and host-write hooks, so AnyPS5 stops re-copying whole guest heaps each frame. 0.9.104 fixes the 0.9.103 freeze after ~67 frames (guest allocation still pinned, 60 s): AnyPS5 memory lookups no longer wait on Kyty's memory-operation lock, which a guest thread holds while waiting for those lookups' GPU lease; the shared log now includes AnyPS5, write-watch and pacing lines. 0.9.105 fixes the AnyPS5 crash 'cannot open /proc/self/pagemap' (denied to Android apps), copies guest memory in 1 MiB instead of 16 KiB pieces, logs AnyPS5 memory traffic every 5 s (NOVA_ANYPS5_IO), and (task 5) stops the CRI audio thread spinning on AudioOut2 queue-level polls: a repeated full-queue poll waits for the next audio grain (NOVA_AUDIO_POLL). 0.9.105 confirmed on device: CRI audio thread ~3-5% of a core (was ~100%). 0.9.106 measures why the CPU and GPU take turns in Kyty mode (GPU ~63% busy at ~15 FPS): blocking CPU-for-GPU waits by call site (NOVA_CPU_WAIT), submission call sites for Wonder Boy, and the shared log keeps the latest timing lines. No speed change is claimed for this build. 0.9.107 adds sampled per-draw GPU timing for Wonder Boy (NOVA_GPU_DRAW: which pipelines cost the ~42 ms gameplay frame; 1 s of every 10 s). Measurement only; no speed change. 0.9.108 (task 1): a CPU write fault into GPU-written buffer memory reads back the GPU-written neighbourhood (256 KiB window) in the same single GPU wait instead of one wait per 4 KiB page (Luna spent 2-3 s of every 5 s in these waits); turning off 'Write-fault window' disables it. GPU draw timing also enabled for Luna (PPSA36257). Device validation required. 0.9.109: GPU timing showed Wonder Boy renders every main pass at 3840x2160 (4K) even with a 1080p display; 'Render resolution' is now an absolute height, so 1080p really renders 1920x1080 on 4K games (it previously meant native on them). 0.9.110: 0.9.109 still drew Wonder Boy at 4K because depth buffers and images created native were never scaled, so passes fell back to native; render passes now scale colour and depth together (scaling native targets down in place after two eligible passes) and whole-image CPU uploads keep the scale. Expect possible graphics glitches; Render resolution Native turns it off. 0.9.111: frames were serialized (~25 ms CPU recording then ~39 ms GPU, GPU only ~57% busy); Kyty now submits recorded work between render passes every 64 draws so the GPU runs while the CPU records (NOVA_EARLY_SUBMIT). Also reports why passes do not scale (NOVA_RESCALE_GROUP), since 0.9.110 still scaled only 8 images. 0.9.111 measured on device: Wonder Boy gameplay 18-24 FPS (was 14-16), GPU now 83-95% busy. 0.9.112 adds an Upscaling filter option (Bilinear / Bicubic / ScaleForce-style sharp) for the final stretch to the screen, and reports how many passes really render scaled and their real render size. 0.9.112 measured on device: about 98% of Wonder Boy passes really render scaled (1279x720 at 720p), but GPU time did not drop with resolution. 0.9.113 (task 1) records CPU-to-GPU buffer uploads ahead of the current command buffer instead of ending the render pass and draining the GPU for each one (~29 per frame in Wonder Boy), only when that cannot change what any command reads: the uploaded pages were not CPU-written since that command buffer began and the buffer has no other recorded write in it; everything else stays in order (NOVA_HOIST_UPLOADS lines; NOVA_HOIST_UPLOADS=0 disables). Game folders added to the library (and installed PKGs) now get a .nomedia marker, so game icons, backgrounds and texture images stop appearing in the phone photo gallery. 0.9.113 measured on device: about 40% of uploads hoisted, Wonder Boy still 18-23 FPS with the GPU ~70% busy; sysmem made the heaviest draws slower, and with VRS off the top pipeline costs ~2.4 ms per draw, so the cost is per-pixel work in the translated shaders. 0.9.114 (measurement for the shader work): for Wonder Boy and Luna the GPU timing report now describes the translated shaders of the slowest pipelines (NOVA_GPU_SHADER: instruction mix, loops, texture samples, memory loads by kind including buffer-device-address loads) and saves their SPIR-V to Download/NovaPS5-shaders when All files access is granted; the upload report says why uploads stay in order. No shader or pipeline is changed and no FPS change is claimed. Hellblade from an SD card spent 50-90 ms on each missing optional file (a directory re-listing per lookup), so boot crawled; game-folder (/app0) directory listings are now read once and reused (NOVA_APP0_DIR_CACHE=0 disables). Wolverine stops on an unsupported shader texture table; its error now names the exact difference so it can be supported next. 0.9.114 measured on device: Hellblade got through its settings files (~4300 lookups, resolution now fast) and reached GPU start after ~74 s, but each missing file still cost ~55 ms in the native stat on the SD card. 0.9.115: a game-folder path absent from the cached directory listing is answered as not found without touching the SD card; guest writes under /app0 refresh the listings. Contains the 0.9.90-test1 candidates (overlays 0969-0989, unchanged), AnyPS5 renderer updated to upstream eaf7ee8, and a per-game Advanced graphics option: GPU renderer = Kyty
